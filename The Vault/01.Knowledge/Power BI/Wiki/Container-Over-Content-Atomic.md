# Container Over Content — Layout Priority Atomic

> **Type:** atomic
> **Routed to:** Power BI
> **Primary source:** Isabelle Bittar — 2024-03-02

## The Principle

> Spend more time defining the container/layout of a report than working with the actual data.

## Why It Matters

The best data in the world is worthless if users can't find it, understand it, or act on it. The layout determines:
- What users see first
- How they navigate the report
- How much cognitive effort it takes to find insights
- Whether the report gets used or ignored

## The Implication

- **Container first:** Plan the layout, navigation, hierarchy, and user actions before choosing or configuring visuals
- **Content second:** Data work (DAX, modeling, data shaping) comes after the UX structure is defined
- **Test third:** Validate the layout with real users before finalizing

## Common Mistake

Authors spend weeks perfecting DAX measures and data models, then spend an hour throwing visuals on a page. The result: technically correct reports that no one uses.
